# Note Portal Windows alpha 实机测试计划

本计划供另一台 Windows 电脑上的测试者执行，重点是 **Windows on ARM**。它验证已发布的安装包，不把 CI 编译成功当作安装、运行成功。测试者只记录问题；未经项目负责人要求，不修改源码、不提交 PR、不重新发布。

## 1. 先确认版本与机器

1. 从[公开 Releases](https://github.com/Sumire-no-kai/Personal-Study-Portal-Framework/releases)下载要测试的版本，不用 CI 临时 artifact 代替正式下载路径。保存 Release 链接、标签、安装包完整文件名和 `SHA256SUMS.txt`。**发布前复测例外：**如果有进行中的发布检查清单 issue（例如 0.1.1-alpha.1 的 [#44](https://github.com/Sumire-no-kai/Personal-Study-Portal-Framework/issues/44)），就改用该 issue 最新评论指定的 Actions 构建，按该清单逐项测试，并把结果评论到该 issue；记录运行编号和提交号。这类构建没有 `SHA256SUMS.txt`，改为记录下载的产物和安装包的 SHA-256。
2. 用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 核对安装包与校验文件。不一致就停止安装并报告。
3. 记录 Windows 版本与构建号、设备的处理器/系统架构、默认浏览器、是否已有 Edge WebView2 Runtime，以及测试前是否装过 Note Portal。
4. Windows on ARM 优先选择文件名含 `arm64-setup.exe` 的包。x64 包在 ARM 机器上即使通过模拟运行，也不能算原生 ARM64 验证。如果所选 Release 没有 ARM64 包，记录“ARM64 包未发布”，不要把 x64 结果写成 ARM64 通过。
5. Tauri 的 ARM64 NSIS 安装器外壳可能通过 x86 模拟运行，安装后的 Note Portal 应用主体仍应是原生 ARM64。安装器进程显示 x86 不是应用构建失败；应检查安装后的应用进程或可执行文件架构。

只在可信的测试机或虚拟机上处理未签名安装包。SmartScreen、杀毒软件或 WebView2 安装提示要截图记录；不要为了测试关闭系统防护，也不要在不信任的电脑上强行放行。

## 2. 使用可丢弃的测试资料库

不要选择真实笔记、课程资料、同步盘或生产目录。把仓库内的两个虚构示例**复制**到 Windows 临时目录，例如 `NotePortalQA` 下的 `general` 与 `study`：

- `servers/desktop-windows/examples/general-library-template/`
- `servers/desktop-windows/examples/study-library-template/`

选择的是各示例的**最外层文件夹**；Study 不要直接选择里面的 `content/`。测试前记录全部测试 `.md` 与图片的文件名、大小和 SHA-256；之后比较。只有明确点击“创建笔记”或“创建 Week 模板”时，才允许出现预览过的新文件；任何扫描、刷新、阅读、搜索和诊断都不应修改原文件。

测试缺陷时可以在这些**副本**里创建、编辑、重命名或删除测试文件；不要把这些操作施加到仓库原始示例上。

## 3. 必须测：安装与首次使用

| 编号 | 操作 | 预期 |
|---|---|---|
| W-01 | 安装 Release 中的 `.exe`，从开始菜单启动；记录安装器警告与是否需要管理员权限 | 安装完成，小控制窗口出现，不崩溃；默认浏览器是阅读界面，不是大应用窗口 |
| W-02 | 首次启动先不勾选同意；查看完整提示，然后点“不同意并退出”；再次启动 | 同意前不能选择资料库、启动服务或打开阅读器；退出后没有残留的本机监听服务；再次启动仍显示提示 |
| W-03 | 勾选并同意；检查“一分钟了解”对话框、“使用指南” | 引导说明 General/Study、选文件夹、浏览器阅读与外部工具更新 `.md`；不声称内置 AI |

## 7. 可选的第二轮检查

- 开启“登录电脑后在任务栏静默启动服务”，重新登录：服务可用但不自动弹浏览器；测试完恢复原设置。
- 测试端口被占用时“打开阅读器”仍可用；不要为此关闭其他用户进程。
- 在临时副本中测试无效 frontmatter、重复 `id`、过大的 Markdown/图片、指向资料库外的链接或符号链接：应诊断或拒绝，而不是泄露外部文件或破坏上一个有效页面。
- 记录应用空闲 5 分钟的 CPU、内存和启动耗时；浏览器与 Note Portal 进程分开记录。alpha 阶段先测量，不把 CI 编译成功当作性能达标。
- 以键盘完成主要按钮操作，并在 Windows 显示缩放 100% 与 150% 下查看小窗口、对话框、目录树是否能正常滚动和阅读。
- 最后卸载应用；临时资料库应保持原样。不要把用户设置是否删除当成笔记是否保留的替代证据。

## 8. 交回结果的格式

每项写 **通过 / 失败 / 未测**。失败项附：版本标签、Windows 构建号与架构、安装包名、复现步骤、实际/预期结果、截图或日志、是否只在 ARM64 出现。另给出安装器大小、应用进程架构、动态刷新耗时、空闲 CPU/内存。

不要在公开 Issue、仓库内的测试记录、截图或日志中暴露真实笔记正文、私人绝对路径、会话令牌、学校受限资料，以及本机 IP 地址、计算机名或 Windows 用户名。测试者可以报告必要的脱敏相对路径。

Windows x64 的最新公开安装包复测见 [2026-09-25 alpha.3 测试记录](WINDOWS_X64_TEST_RUN_2026-09-25_ALPHA3.md)；[2026-09-23 alpha.1/alpha.2 记录](WINDOWS_X64_TEST_RUN_2026-09-23.md)保留作历史对照。逐项状态和测试机环境分别记在对应记录中。

### W-12 缺陷复现记录（本机 UI 文本记录）

1. 在 General 副本点击“＋ 创建笔记”，填标题 `QA W12 ARM Note`，文件夹保持“资料库最外层”。
2. 对话框显示“创建一篇笔记”“只创建一个新的 .md 文件；已有文件不会覆盖。”“笔记标题”“放在哪个文件夹”“创建笔记”；输入标题后仍未显示将创建的相对路径或文件名。这一点在重新打开对话框、输入 `QA Preview Check` 后再次复现。
