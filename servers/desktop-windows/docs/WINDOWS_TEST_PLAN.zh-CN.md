# Note Portal Windows alpha 实机测试计划

本计划供另一台 Windows 电脑上的测试者执行，重点是 **Windows on ARM**。它验证已发布的安装包，不把 CI 编译成功当作安装、运行成功。测试者只记录问题；未经项目负责人要求，不修改源码、不提交 PR、不重新发布。

## 1. 先确认版本与机器

1. 从[公开 Releases](https://github.com/Sumire-no-kai/Personal-Study-Portal-Framework/releases)下载要测试的版本，不用 CI 临时 artifact 代替正式下载路径。保存 Release 链接、标签、安装包完整文件名和 `SHA256SUMS.txt`。
2. 用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 核对安装包与校验文件。不一致就停止安装并报告。
3. 记录 Windows 版本与构建号、设备的处理器/系统架构、默认浏览器、是否已有 Edge WebView2 Runtime，以及测试前是否装过 Note Portal。
4. Windows on ARM 优先选择文件名含 `arm64-setup.exe` 的包。**`v0.1.0-alpha.1` 只有 x64 包**；它在 ARM 机器上即使通过模拟运行，也不能算原生 ARM64 验证。如果所选 Release 没有 ARM64 包，记录“ARM64 包未发布”，不要把 x64 结果写成 ARM64 通过。
5. Tauri 的 ARM64 NSIS 安装器外壳可能通过 x86 模拟运行，安装后的 Note Portal 应用主体仍应是原生 ARM64。安装器进程显示 x86 不是应用构建失败；应检查安装后的应用进程或可执行文件架构。

只在可信的测试机或虚拟机上处理未签名安装包。SmartScreen、杀毒软件或 WebView2 安装提示要截图记录；不要为了测试关闭系统防护，也不要在不信任的电脑上强行放行。

## 2. 使用可丢弃的测试资料库

不要选择真实笔记、课程资料、同步盘或生产目录。把仓库内的两个虚构示例**复制**到 Windows 临时目录，例如 `NotePortalQA` 下的 `general` 与 `study`：

- `servers/desktop-windows/examples/general-library-template/`
- `servers/desktop-windows/examples/study-library-template/`

选择的是各示例的**最外层文件夹**；Study 不要直接选择里面的 `content/`。测试前记录全部测试 `.md` 与图片的文件名、大小和 SHA-256；之后比较。只有明确点击“创建笔记”或“创建 Week 模板”时，才允许出现预览过的新文件；任何扫描、刷新、阅读、搜索和诊断都不应修改原文件。

测试缺陷时可以在这些**副本**里创建、编辑、重命名或删除测试文件；不要把这些操作施加到仓库原始示例上。

## 3. 必须测：安装与首次使用

| 编号 | 操作 | 预期 |
|---|---|---|
| W-01 | 安装 Release 中的 `.exe`，从开始菜单启动；记录安装器警告与是否需要管理员权限 | 安装完成，小控制窗口出现，不崩溃；默认浏览器是阅读界面，不是大应用窗口 |
| W-02 | 首次启动先不勾选同意；查看完整提示，然后点“不同意并退出”；再次启动 | 同意前不能选择资料库、启动服务或打开阅读器；退出后没有残留的本机监听服务；再次启动仍显示提示 |
| W-03 | 勾选并同意；检查“一分钟了解”对话框、“使用指南” | 引导说明 General/Study、选文件夹、浏览器阅读与外部工具更新 `.md`；不声称内置 AI |
| W-04 | 进入“设置与条款”和“关于” | 能重看完整条款、同意版本与时间；Buy Me a Coffee 是自愿链接，不挡住功能 |

如果已有旧安装，首次同意可能已经保存在本机。请使用新的 Windows 测试用户/干净虚拟机测试 W-02；不要擅自删除现有用户配置来制造首次启动状态。

## 4. 必须测：资料库与浏览器

| 编号 | 操作 | 预期 |
|---|---|---|
| W-05 | 选择 General 示例，先看识别预览，再确认 | 根目录和子文件夹下的普通 `.md` 出现在树中；`draft: true` 不进入正常导航与搜索；未识别数与原因可信 |
| W-06 | 选择 Study 示例最外层 | `content/2026-semester-2/DEMO101/week-01/week-01-notes.md` 显示为 Semester → Unit → Week；`inbox/` 单独显示；相对图片路径可用 |
| W-07 | 在 Study 副本的 `week-01/` 加入 `summary.md`，再加一个错误命名的主笔记 | 额外文件不被误认作主笔记；诊断显示相对路径、原因与建议，不自动移动或改名 |
| W-08 | 打开阅读器，检查目录、正文、标题、搜索、图片；在测试副本中加入标题、列表、表格、公式、中文路径内容再查看 | 浏览器能正常阅读，桌面版不会出现不能使用的内置 AI 入口或旧设备专属状态；内容由本地文件生成 |
| W-09 | 用编辑器修改正在阅读的 `.md` 并保存；再新增、重命名、删除一篇测试 `.md`，也试一次先写临时文件再改名为 `.md` | 不重启应用就能更新正文、导航与搜索；临时文件不闪现为正式笔记；当前阅读位置尽量保持。记录每次保存到更新的秒数 |
| W-10 | 选空文件夹、换回示例资料库，试“立即刷新”和“打开文件夹” | 空库显示 0 篇且不崩溃；更换资料库前可预览；资源管理器打开正确目录 |

## 5. 必须测：数据安全与服务生命周期

| 编号 | 操作 | 预期 |
|---|---|---|
| W-11 | 对比资料库选择、扫描、刷新、阅读、搜索、退出前后的文件名和 SHA-256 | 除测试者自己编辑的文件外，应用不移动、重命名、覆盖、删除或改写 `.md` 与附件 |
| W-12 | General 中“创建笔记”、Study 中“创建 Week 模板”；再尝试创建同一路径 | 只创建预览过的新路径；第二次拒绝覆盖，首次文件内容不变 |
| W-13 | 关闭小窗口，再从系统托盘显示窗口；依次测试“停止服务”“启动服务”“退出” | 关窗口不等于退出；停止后浏览器不再读取；重新启动后可读；退出后服务与进程结束 |
| W-14 | 应用运行时再次启动安装后的应用 | 只保留一个实例和一个本地服务，已有控制窗口被唤起 |
| W-15 | 查看服务监听地址；用无会话的浏览器隐私窗口直接访问同一端口，另检查局域网地址 | 服务只绑定 `127.0.0.1`；无授权会话不能读笔记；局域网不能访问。不要复制含会话令牌的启动 URL 到报告里 |
| W-16 | 安装完成后断开网络，再打开现有本地资料库和搜索 | 已具备 WebView2 的机器上本地阅读仍可用；如果安装阶段需联网下载 WebView2，应与运行阶段分开记录 |

## 6. Windows on ARM 专项

| 编号 | 操作 | 预期 |
|---|---|---|
| A-01 | 记录机器确为 ARM64；安装 Release 中的 `arm64-setup.exe`；查看安装后的应用进程或 PE 架构 | **应用主体**为 ARM64，而不只是 x64 程序在模拟下能打开；若无法验证，标记“未验证”，不要猜测 |
| A-02 | 在 ARM 设备完成 W-02 至 W-16，特别观察 WebView2、小窗口、托盘、默认浏览器、文件夹选择器、自动刷新 | 功能与 x64 预期一致；任何 ARM 独有错误附完整复现步骤 |
| A-03 | 如设备上同时试过 x64 和 ARM64 包，分别记录结果；不要让两次安装互相覆盖测试证据 | x64 模拟兼容性与原生 ARM64 兼容性分别报告；以 ARM64 包为主要结论 |

## 7. 可选的第二轮检查

- 开启“登录电脑后在任务栏静默启动服务”，重新登录：服务可用但不自动弹浏览器；测试完恢复原设置。
- 测试端口被占用时“打开阅读器”仍可用；不要为此关闭其他用户进程。
- 在临时副本中测试无效 frontmatter、重复 `id`、过大的 Markdown/图片、指向资料库外的链接或符号链接：应诊断或拒绝，而不是泄露外部文件或破坏上一个有效页面。
- 记录应用空闲 5 分钟的 CPU、内存和启动耗时；浏览器与 Note Portal 进程分开记录。alpha 阶段先测量，不把 CI 编译成功当作性能达标。
- 以键盘完成主要按钮操作，并在 Windows 显示缩放 100% 与 150% 下查看小窗口、对话框、目录树是否能正常滚动和阅读。
- 最后卸载应用；临时资料库应保持原样。不要把用户设置是否删除当成笔记是否保留的替代证据。

## 8. 交回结果的格式

每项写 **通过 / 失败 / 未测**。失败项附：版本标签、Windows 构建号与架构、安装包名、复现步骤、实际/预期结果、截图或日志、是否只在 ARM64 出现。另给出安装器大小、应用进程架构、动态刷新耗时、空闲 CPU/内存。

不要在公开 Issue、截图或日志中暴露真实笔记正文、私人绝对路径、会话令牌或学校受限资料。测试者可以报告必要的脱敏相对路径。

本轮 Windows x64 测试记录见 [2026-09-23 测试记录](WINDOWS_X64_TEST_RUN_2026-09-23.md)；逐项状态和测试机环境均在该记录中。
